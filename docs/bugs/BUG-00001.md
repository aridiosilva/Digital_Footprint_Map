# BUG-00001 — Whitespace em campo `confidence` de CSV causa `ValueError`

| Campo | Valor |
|---|---|

| **Data encontrado** | 2026-08-26 |
| **Data corrigido** | 2026-08-26 |
| **Componente afetado** | `src/pegada/importers.py` — F-0004: Evidence Importers |
| **Severidade** | Medium |
| **Status** | Verified |

---

## Descrição

A função `from_csv()` lançava `ValueError: could not convert string to float: ' '`
quando uma célula da coluna `confidence` continha apenas um ou mais espaços em
branco (por exemplo, uma célula com `" "`).

O comportamento esperado era tratar células vazias ou de espaço como o valor
padrão `0.5`, exatamente como células ausentes são tratadas.

---

## Causa raiz

A expressão usada para converter o valor era:

```python
confidence=float(r.get("confidence") or .5)
```

O operador `or` em Python avalia a expressão à esquerda como booleano.
A string `" "` (somente espaços) é **truthy** — não é vazia, portanto o `or`
não substitui pelo padrão `0.5`. O valor `" "` é então passado diretamente a
`float()`, que não consegue converter uma string de espaços e lança `ValueError`.

### Por que isso não foi percebido antes

Os testes manuais usavam células vazias `""`, que são **falsy** e caem
corretamente no valor padrão. O caso de célula com espaços só foi coberto
quando os testes automatizados foram adicionados (PR #7).

---

## Passos para reproduzir

```python
from pathlib import Path
import tempfile, textwrap

with tempfile.TemporaryDirectory() as d:
    p = Path(d) / "data.csv"
    p.write_text("title,url,confidence\nLivro,urn:1, \n", encoding="utf-8")
    from pegada.importers import from_csv
    from_csv(p, "book")   # raises ValueError before the fix
```

---

## Correção aplicada

**Arquivo:** `src/pegada/importers.py`

```python
# Antes (linha 23)
confidence=float(r.get("confidence") or .5)

# Depois
confidence=float(r.get("confidence", "").strip() or 0.5)
```

A correção adiciona `.strip()` para remover espaços antes do teste de
verdade. Uma string composta apenas de espaços torna-se `""` após strip,
que é **falsy**, portanto o `or 0.5` aplica o valor padrão corretamente.

---

## Testes adicionados

Arquivo: `tests/test_importers.py`

- `test_from_csv_empty_confidence_defaults_to_half` — célula vazia → `0.5`
- `test_from_csv_empty_identity_status_defaults_to_pending` — célula com `" "` → não deve lançar; identity_status → `"pending"`

O segundo teste foi o que revelou o bug durante o desenvolvimento dos testes
da feature F-0004 (PR #7).
